# Подбор автозапчастей (тестовое задание ЮРАЛ)

Клиент на React + Redux (без TypeScript) к API Favorit «Проценка».

**Шаг 1.** Пользователь вводит артикул, после паузы в наборе (от 3 символов) приложение запрашивает производителей.
**Шаг 2.** По клику на производителя — повторный запрос с введённым номером, `brand` и `analogues=on` (как в схеме из документации). Таблица аналогов: название, производитель, артикул, цена, остаток, ближайшая отгрузка; клик по строке раскрывает склады с ценой, остатком и датой отгрузки.

## Запуск

```bash
npm install
cp .env.example .env   # в примере — тестовый ключ из документации API, с ним приходят живые данные
npm run dev
```

Попробуйте артикулы `0189` и `7160500039S` (у MEYLE — больше 700 аналогов).
Без ключа (пустой `VITE_FAVORIT_KEY` или нет `.env`) приложение работает в демо-режиме на встроенных данных; `error` в демо-режиме имитирует сбой сети.

## Решения

- **Стек:** Vite, React 18, Redux Toolkit (`createSlice` + `createAsyncThunk`), Bootstrap 5.
- **Прокси.** API работает по http и не объявляет CORS, поэтому запросы идут через прокси Vite (`/api` → `api.favorit-parts.ru/hs/hsprice`). Для продакшена нужен такой же прокси на своём бэкенде — заодно ключ не будет светиться в браузере.
- **Цена.** Корневое поле `price` в документации помечено «НЕ ИСПОЛЬЗОВАТЬ», поэтому цена берётся со складов: «цена от» — минимальная среди складов с остатком, полный список складов раскрывается по клику.
- **Объём.** Живой API может вернуть сотни аналогов (на MEYLE 7160500039S — 741). Поэтому: по умолчанию «только в наличии», сортировка (цена / остаток / скорость отгрузки), показ по 50 строк с «Показать ещё»; искомая деталь всегда первой.
- **Номер детали.** API отдаёт номер в своём формате (`7160500039/S`, `01-89`); на второй шаг уходит номер, введённый пользователем, как в схеме из документации.
- **Невозвратные позиции.** Запрос идёт с `info=on`, такие позиции помечены.
- **Состояния.** Лоадеры на каждом шаге; ошибки сети, HTTP-ошибки, ошибки API (неверный ключ, лимит запросов и др.) показываются понятным текстом с кнопкой «Повторить». Живой API отвечает не совсем как в документации: на неверный ключ — HTTP 403 и текст «The API key provided is invalid or has been revoked», поэтому тело ответа разбирается при любом статусе, а сообщения распознаются по смыслу. Ответ «не найдено» (массив с одной пустой структурой) отображается как пустой результат.
- **Гонки запросов.** Если пользователь успел ввести новый артикул или выбрать другого производителя, устаревший ответ игнорируется.

## Структура

```

  api/favorit.js       запросы к API, нормализация ответа
  api/mock.js          демо-данные в формате API

  components/          SearchForm, BrandList, OffersTable, Status
```
